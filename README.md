# APS360: Live Handwriting-to-Text (CRNN + CTC)

Reads handwritten words with a CNN + bidirectional LSTM trained with CTC loss on the
IAM words dataset, then (later) runs live on webcam frames.

**Status: step 1 of 6 (data pipeline) is done.** The model, training, augmentation,
baselines and the webcam pipeline are TODO stubs.

## Report outputs
Steps 2 and 3 save everything the progress report needs to `<project folder>/outputs/report/`: figures as PNG
(300 dpi) + PDF sized for the ICLR 5.5-inch text width, tables as CSV + LaTeX booktabs `.tex` (complete `table`
environments: `\input{table_x}` with `\usepackage{booktabs}`), `report_numbers.json` and `report_summary.md`
(every file with a suggested caption). Whichever of Step 2 / Step 3 runs last also writes the CRNN vs Tesseract
comparison (`table_comparison`), scored on exactly the same words.

## Where the data goes
`DATA_ROOT` defaults to `data/iam` inside the repo. Change it with the `HTR_DATA_ROOT`
environment variable or with `--data-root` on any script.
```
DATA_ROOT/ascii/words.txt
DATA_ROOT/ascii/forms.txt          (writer IDs, used by the automatic split)
DATA_ROOT/words/a01/a01-000u/a01-000u-00-00.png
```

## Getting IAM (free, needs registration)
1. Go to https://fki.tic.heia-fr.ch/databases/iam-handwriting-database and click **Register**.
   Use your university email and confirm the account.
2. Log in, open the download page (https://fki.tic.heia-fr.ch/databases/download-the-iam-handwriting-database)
   and download **data/words.tgz** (~800 MB) and **data/ascii.tgz** (small).
3. Unpack them with the helper:
   `python scripts/setup_iam.py --words-tgz words.tgz --ascii-tgz ascii.tgz --out data/iam`
   (or, for any other download such as Kaggle's: unzip it and run `python scripts/setup_iam.py --raw <folder> --out data/iam`)
4. Cite Marti & Bunke (2002) in the report. IAM is for non-commercial research only:
   don't commit it to GitHub (it's in `.gitignore`).

## Running in Google Colab (recommended)
Open `notebooks/APS360_HTR_Step1_Data.ipynb` (on Drive it's "APS360 - HTR Step 1 (Data)") and choose Runtime → Run all.
It's self-contained: it writes all of this code into the session with `%%writefile` cells. It then copies
`archive.zip` from the project's Drive folder, unzips it on Colab's local disk, and auto-detects the IAM layout
(official tgz files, Kaggle `iam_words/`, or a flat folder) with `scripts/setup_iam.py --raw`. Finally it runs the
tests and inspects IAM, saving the outputs to `<project folder>/outputs/`.

## Splits
- If `data/splits/aachen/{train,validation,test}.uttlist` exist and match the data, they're used.
  These are the Aachen writer-independent form lists that most IAM papers use. Words from forms
  not in any list are counted as `not_in_any_split`.
- Otherwise (or with `--split-dir none`), the code builds a deterministic writer-disjoint
  80/10/10 split: writer IDs come from `forms.txt`, or from the form prefix (e.g. `a01`) if
  `forms.txt` is missing. That prefix fallback is only an approximation of writers.

## Writer IDs
The writer-disjoint check and the automatic split need to know who wrote each form. The code uses
`ascii/forms.txt` if your download has it. Otherwise it uses the bundled `data/iam_form_writers.csv`
(1,539 forms, 657 writers; source and checks in `data/iam_form_writers_SOURCE.md`). With it, the
Aachen splits have 283 / 56 / 161 writers and none shared. If neither is available, the check prints
"writer IDs unavailable; Aachen splits are writer-independent by design" instead.

## Truncated words.txt (Kaggle download)
The `words.txt` in some Kaggle copies of IAM stops part-way through a line (e.g. `e07-072-09-`), so
only forms a01–e07 have labels (~44.6k of 115k lines). `setup_iam.py` warns when this happens, and
`inspect_data.py` counts the cut-off line as `malformed_line`. To use all of IAM, put the full
`words.txt` from the official `ascii.tgz` next to `archive.zip` (the notebook picks it up), or pass
`--words-txt` to `setup_iam.py`.

## Filters (counts are printed for the report)
Lines with no label (`malformed_line`) are skipped first. Then, in order: segmentation status `err` (switch with `drop_err`), empty label, characters outside
the charset, label longer than `max_label_len` (32), and missing or unreadable image.
